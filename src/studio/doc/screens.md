# 页面设计（screens/）

对应 `index.md` 架构分解中的 `screens/` 层。每个页面一节：定位、布局结构、关键交互、数据来源与依赖组件。

## 通用约定

- **页面私有组件**：留在 `screens/<page>/` 子目录，两个以上页面复用才提升到 `widgets/`
- **数据状态**：阶段一数据为内存示例，页面只处理空态（`EmptyState`）；加载/错误态待接入数据层时补充
- **导航**：全部页面由 `AppShell` 承载（侧边栏四个入口：首页/架构/成员/健康度）
- **写操作**：页面不直接修改模型；交互产生变更草稿 → 提交数据层（落为 `ChangeRecord`，受控变更 `approval=pending`）。审批流在数据层，界面不实现审批对话框

## HomeScreen — 工作台总览

**定位**：登录后第一屏，聚合组织风险与待办，是「必读处」的入口。

**布局结构**：

```
┌ AppShell（侧边栏：四页面入口）─────────────┐
│ 欢迎区：当前成员、日期                    │
│ 待审批变更  ┌───────────────────────────┐ │
│ （列表）    │ ChangeRecord(pending)     │ │
│ 风险清单    ┌───────────────────────────┐ │
│ （RiskBadge 列表）│ 单点风险聚合        │ │
│ 岗位空缺    ┌───────────────────────────┐ │
│ （列表）    │ departed 成员遗留空缺     │ │
└──────────────────────────────────────────┘
```

**关键交互**：
- 点击待审批变更/风险/空缺条目 → 跳转对应页面并定位到目标
- 风险清单显示 RiskBadge（岗位单人承担、复盘组织者=单人），可展开备选提示

**数据来源**：聚合查询 — `ChangeRecord(approval == pending)`、单点风险重算结果（岗位单人/复盘组织者单人）、`Position`（空缺岗位）。

**状态设计**：无风险无空缺时显示「一切正常」空态（正向确认）。

**依赖组件**：`RiskBadge`、`StatusBadge`、`MemberCard`。

## OrgStructureScreen — 架构页

**定位**：组织架构的浏览与变更入口，是「唯一权威源」的可视化。

**布局结构**：

```
┌ AppShell ─────────────────────────────────┐
│ ┌ 左侧：架构树 ──┐ ┌ 右侧：详情面板 ──────┐│
│ │ DepartmentTree │ │ 选中部门/岗位详情     ││
│ │ 部门 → 岗位     │ │ 编制数 / 任职成员     ││
│ │ → 汇报链路      │ │ [发起变更] [版本历史] ││
│ └───────────────┘ └──────────────────────┘│
└────────────────────────────────────────────┘
```

**关键交互**：
1. 浏览：展开树查看部门/岗位/汇报链路；编制 `filled > headcount` 处显示超编警示
2. 发起变更：填写变更表单（改什么、为什么）→ 提交数据层（`ChangeRecord`，`approval=pending` 待审批）
3. 版本历史：`ChangeHistoryPanel` 时间线查看，diff 看数据层仓库提交

**数据来源**：`Department`、`Position`、`ReportRelation`、`ChangeRecord`。

**依赖组件（页面私有）**：`DepartmentTree`、`ChangeHistoryPanel`、编制表（随状态页/时间表移除后仅本页使用，按复用规则留在此处）。共享组件：`StatusBadge`、`EmptyState`。

## MembersScreen — 成员页

**定位**：成员与职责的查看中心，解决「一人多岗职责边界模糊」与「关键人风险」。

**布局结构**：

```
┌ AppShell ─────────────────────────────────┐
│ 成员列表（MemberCard）                     │
│  张三 · 创始人/产品（兼任） · 汇报: —      │
│  李四 · 研发/运维（兼任） · 汇报: 张三     │
│ ┌ 成员详情（点选展开）───────────────────┐ │
│ │ 岗位列表（positions 全部任职）         │ │
│ │ 汇报对象 / 单点风险标注                │ │
│ │ ── 成员变动影响（departed 成员）─────  │ │
│ │ 岗位空缺：产品负责人                   │ │
│ │ 职责悬空：复盘组织                     │ │
│ └────────────────────────────────────────┘│
└────────────────────────────────────────────┘
```

**关键交互**：
- 点击成员查看详情：岗位（兼任=多个）/汇报对象/单点风险
- 单点风险：系统分析某岗位仅一人承担 → 标注 `RiskBadge`，提示备选人
- 成员变动影响（`Member.status = departed`）：展示其遗留的岗位空缺与职责悬空（由人事云事件经数据层写入的事实），提示重新指定——**不实现交接流程**（归人事云）

**数据来源**：`Member`、`Position`、`ReportRelation`、`Retrospective`（组织者单点分析）。

**依赖组件**：`MemberCard`、`RiskBadge`、`StatusBadge`、`EmptyState`。

## HealthScreen — 组织健康度页

**定位**：组织云的体检中心（「体检纠偏」支柱）。基于 OHI 九维度从组织数据推导健康度，产出组织温度计与体检结论；复盘是机制健康的数据源，保留独立记录页。概念与分级约定见 `data/context/handbook/health.md`。

**布局结构**（Tab 双页签）：

```
┌ AppShell ─────────────────────────────────┐
│ AppBar: 组织健康度                        │
│ Tab: [健康度总览] [复盘记录]              │
├─ Tab1 健康度总览 ────────────────────────┤
│ 组织温度计（温度 + 进度条 + 维度统计）    │
│   · 36.6°C · 整体注意 · 8 维已评估        │
│ OHI 九维度卡片（逐一展开）                │
│   · 方向 Direction  · 指标 + 等级徽章     │
│   · 外部导向 External · 待问卷            │
├─ Tab2 复盘记录（左列表 + 右详情）────────┤
│ 复盘列表（日程/组织者/状态） [新建]       │
│ 复盘详情：状态流转（标记已召开/取消）     │
│   · 组织者卡 / 参与人 / 风险标注          │
│   · 结论沉淀（追加/删除）                 │
└────────────────────────────────────────────┘
```

**关键交互**：
- 温度计：已评估维度计分（良好 3/注意 2/警示 1）平均 → 整体等级与温度（36.5°C 基准）；未评估维度（外部导向）标注待问卷
- 维度卡片：每个维度显示名称（中英）、关注问题、当前指标与等级徽章
- 复盘记录：新建/编辑（日期选择器、组织者、参与人）、状态流转（待召开 → 已召开/已取消）、组织者=单人风险标注、组织者离职提醒重新指定、结论沉淀追加与删除
- 复盘召开率、结论沉淀率等指标实时反馈到健康度总览

**数据来源**：`HealthReport`（`computeHealthReport` 由组织数据推导）、`Retrospective`、`Member`。

**依赖组件**：`MemberCard`、`RiskBadge`、`StatusBadge`、`EmptyState`。温度计与维度卡片为页面私有组件。
